# KVB Stage 0 Compatibility, Determinism & Cross-Adapter Proof Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Freeze the final Stage 0 bundle shape as committed bytes and prove the stage's cross-cutting guarantees on them: the current decoder reads new bundles through required sections + routing graph, identical canonical inputs compile byte-identically, and the native addon and browser module agree per capability outcome.

**Architecture:** One new committed fixture — `tests/fixtures/stage0.kvb` (minimal-imdf + network + facilities + §8, cut once against the final shape) — plus three committed crafted-outcome fixtures (unsupported version / invalid / disabled-by-dependency), all generated by the extended `compile_fixture` example (zstd is a regular dep, so the example can hand-build payloads). The compatibility proof strips §8 from the fixture in-test (the `rebuild_payload`/`wrap_payload_for_test` infra from #38) and asserts content + routing equality. The cross-adapter parity test lives in the server suite (which has `@kiriko/node`) with `@kiriko/wasm` added as a devDependency — per-outcome capability equality on the same frozen bytes. The Tokyo gate is data-gated: the registered JR East dataset is not in this clone, so a gated test/runner executes it when the data path exists and the missing prerequisite is stated plainly.

**Tech Stack:** Rust (kiriko-bundle, kiriko-route), the bundle integration suite, TS (server vitest + wasm), zstd (dep of kiriko-bundle).

## Global Constraints

- TDD: no production code without a failing test first.
- Commit per logical change, on `feat/kvb-stage0-proof` off `main`.
- The fixtures are frozen: a test must fail if the committed bytes drift from what the current code produces (golden pattern), and the crafted fixtures are pinned by sha256.
- The compatibility comparison strips §8 (directory row + bytes) and re-wraps — the derived bundle is a valid `kvb1` with the same content minus §8; nothing else changes.
- Parity: same bytes → identical capability reports from native inspect and wasm decode, per outcome (available, absent, unsupportedVersion, invalid, disabledByDependency).
- The registered JR East Tokyo dataset is **not available in this environment** — the gate runs when `KIRIKO_TOKYO_FIXTURES` (documented default `tokyo station/` sibling of the repo) exists; otherwise it skips with a clear message. This is a stated prerequisite, not silently dropped.
- Verification gates: `cargo test --manifest-path core/Cargo.toml --workspace`, `pnpm exec tsc --noEmit`, `pnpm --dir server exec tsc --noEmit`, `pnpm exec vitest run`, `pnpm --dir server exec vitest run`.
